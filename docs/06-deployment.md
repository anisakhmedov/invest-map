# Развёртывание, домен, резервные копии

Всё нужное лежит в папке `deploy/`. Сайт работает в Docker: одна команда поднимает веб-приложение, базу данных, файловое хранилище, HTTPS и ночные резервные копии.

## Что нужно заранее

| Что | Подробности |
|-----|-------------|
| Сервер (VPS) | Linux (Ubuntu 22.04/24.04), от 2 vCPU, 4 ГБ ОЗУ, 40 ГБ диска + место под копии. Белый IP-адрес. |
| Домен | Например `invest.example.uz`. Продлевается раз в год (модуль 10 коммерческого предложения). |
| DNS | Записи `A` для `домен` и `www.домен` на IP сервера. Сертификат выпустится только после того, как DNS обновится. |
| Docker | Docker Engine 24+ и плагин Compose v2 на сервере. |
| Почта (по желанию) | Данные SMTP-сервера (`SMTP_URL`) и адрес отправителя `MAIL_FROM` на вашем домене (настройте SPF/DKIM). Без них письма ждут в очереди (`EmailOutbox`), всё остальное работает. |
| Порты | Открыты только 80 и 443 (и SSH с ограничением по IP). Порты базы и хранилища наружу не публикуются. |

## Первый запуск

```bash
git clone <репозиторий> investmap && cd investmap/deploy   # или скопируйте папки apps/ и deploy/
cp .env.example .env
nano .env                                                   # заполните все значения
docker compose -f docker-compose.prod.yml up -d --build
docker compose -f docker-compose.prod.yml logs -f web
```

Секреты генерируйте командой `openssl rand -base64 36`. `AUTH_SECRET` — не короче 32 символов. Сервер **откажется стартовать** с пустыми значениями, заглушками вроде `change-me`, паролями разработки и адресом сайта без `https://` (`src/lib/env-check.ts`).

При первом старте сервис `migrate` применяет миграции, создаёт роли и (если заданы `SEED_ADMIN_EMAIL` / `SEED_ADMIN_PASSWORD`) первого главного администратора. После успешного входа **удалите эти две строки из `.env`** и выполните `docker compose -f docker-compose.prod.yml up -d`.

Проверка: `https://домен/api/health` отвечает `{"status":"ok"}`; вход в админку — `https://домен/ru/admin`.

## Обновление сайта

```bash
git pull                                    # новая версия кода
docker compose -f docker-compose.prod.yml up -d --build
```

Миграции применяются автоматически. Перед обновлением с изменениями базы сделайте копию (см. ниже: «Копия по требованию»).

## Резервные копии

| Что | Как часто | Где лежит | Срок хранения |
|-----|-----------|-----------|---------------|
| База данных (`pg_dump`, формат custom) | каждую ночь в 02:00 по Ташкенту и при каждом запуске | том `backups`, `/backups/db` | `BACKUP_KEEP_DAYS` дней (по умолчанию 14) |
| Загруженные файлы (медиатека, вложения обращений) | каждую ночь | том `backups`, `/backups/media` | зеркало без удаления: файл, удалённый по ошибке, остаётся в копии |

Копия по требованию:

```bash
docker compose -f docker-compose.prod.yml restart backup-db   # делает дамп сразу при старте
```

**Важно:** том `backups` лежит на том же сервере, что и сайт. Он защищает от ошибок и сбоев приложения, но не от потери самого сервера. Обязательно настройте вынос копий на другую машину или в облако, например раз в сутки:

```bash
docker run --rm -v investmap-prod_backups:/backups:ro -v ~/.ssh:/root/.ssh:ro alpine \
  sh -c 'apk add --no-cache rsync openssh-client && rsync -a /backups/ user@резервный-сервер:/srv/investmap-backups/'
```

(или `rclone` в облачное хранилище). Копии содержат персональные данные посетителей и не шифруются: храните их с ограниченным доступом (шифрование диска или `rclone crypt`). Включите также снимки диска у хостинг-провайдера.

### Восстановление

```bash
cd deploy
./restore.sh list                          # какие копии есть
./restore.sh db investmap-20261025T210000Z.dump   # заменяет базу (спросит подтверждение)
./restore.sh media                         # возвращает файлы в хранилище
```

Раз в квартал проверяйте восстановление на тестовой машине: копия, из которой ни разу не восстанавливались, — это предположение, а не копия.

## HTTPS и безопасность

- Сертификат Let's Encrypt выпускает и продлевает Caddy сам; хранится в томе `caddy-data` (не удаляйте его).
- Приложение отправляет заголовки безопасности (CSP, HSTS, запрет встраивания) — см. `next.config.ts`.
- Веб-контейнер работает не от root. База и хранилище доступны только внутри сети Docker.
- Caddy передаёт приложению реальный адрес клиента; ограничение частоты входов и отправки обращений опирается на него.
- Обновляйте систему сервера (`unattended-upgrades`) и образы (`docker compose pull` + `up -d --build` раз в месяц).
- Вход по SSH — только по ключам, `PasswordAuthentication no`; брандмауэр (`ufw allow 80,443,22`).

## Мониторинг

- Адрес для сервисов проверки доступности (UptimeRobot и т. п.): `https://домен/api/health` (503, если база не отвечает).
- Логи: `docker compose -f docker-compose.prod.yml logs --tail 200 web`.
- Журнал действий сотрудников — в админке, раздел «Журнал аудита».
- Состояние копий: `docker compose -f docker-compose.prod.yml logs --tail 20 backup-db backup-media` (строки `backup ok` / `FAILED`).

## Передача заказчику (чек-лист)

- [ ] Домен оформлен на заказчика; доступ к регистратору и DNS передан.
- [ ] Доступ к серверу (SSH-ключи заказчика), к хостинг-панели.
- [ ] Файл `.env` передан безопасным способом (менеджер паролей), копия хранится отдельно от сервера.
- [ ] Созданы личные учётные записи сотрудников (раздел «Пользователи»); учётная запись первичной настройки отключена.
- [ ] Проверено: вход, создание страницы и новости, загрузка файла, отправка тестового обращения, получение ответа по ссылке.
- [ ] Проверено восстановление базы и файлов из копии.
- [ ] Вынос копий на другую машину настроен и проверен.
- [ ] Настроена отправка почты (`SMTP_URL`) и проверено письмо о новом обращении.
- [ ] Карта: подложка OpenStreetMap подходит только для небольших объёмов; для боевой нагрузки нужен свой тайл-сервер или платный провайдер.
- [ ] Заказчику переданы документы: `docs/01-TZ.md`, `docs/02-architecture.md`, это руководство.
- [ ] Согласованы ежегодное продление домена и хостинга (модуль 10) и кто за него отвечает.

## Что не покрыто

- Горизонтальное масштабирование (несколько копий приложения): кэш и ограничения частоты хранятся в памяти одного процесса.
- Автоматическая проверка восстановления — выполняется вручную по расписанию заказчика.
- Свой тайл-сервер для карты и XLSX-импорт — отдельные задачи.
